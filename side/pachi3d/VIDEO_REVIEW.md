# 完成した動画の採点（品質審査担当ミル）

2026-11-22 オーナー指示「動画そのものの採点も足してほしい」。台本はオフィスでミルが採点しているが、完成した動画（見やすさ・豪華さ・テンポ・音）はここで採点する。

## 流れ（pachi-sim-video スキルの「6.5」）

1. 本番の描き出しが終わったら、材料を作る
   `python3 side/pachi3d/video_review.py <動画.mp4>`（約1分。動画と同じフォルダの review/ に metrics.json と sheet_*.png）
2. **機械の決まりに引っかかった所**（metrics.json の problems）は、点数に関係なく直す
3. Agent ツールで**サブエージェント「ミル」**を1体立ち上げ、下の「ミルへの頼み方」をそのまま渡して採点させる（作った本人ではなく別のエージェントに採点させる＝甘くならないため）
4. **85点以上で合格**。届かなければ「直す所」を直して描き出し直し → 1 から。**作り直しは2回まで**。2回でも届かなければ、残った点数と直しきれなかった所をオーナーへの報告に書いて、オーナーに判断してもらう
5. 採点結果を `<動画のフォルダ>/review.md` に保存し、点数をオーナーへの報告と ops/log に1行書く（例：動画の採点 78→88点）
6. 直す時に、時間がかかる本番の描き出しを何度もしないこと：直した所だけ `render --start S --end S+10` で10秒テストし、snapshot で見てから本番

## ミルへの頼み方（そのまま渡す）

```
あなたは品質審査担当のミル。辛口だが、動画を良くするために言う。視聴者の目で、完成した動画を採点する。
読む物：
- <フォルダ>/review/metrics.json（機械で測った数字。problems は必ず直す所）
- <フォルダ>/review/sheet_*.png（一定の間隔で切り出した画面の一覧。左上が時刻）を Read で全部見る
- 台本（字幕の文）と description.txt
採点表（100点）：
| 見やすさ 20 | スマホの小さい画面で、文字が大きく読めるか。字幕と図・アリスが重なっていないか。はみ出し・小さすぎる文字・背景と文字の色が近い所が無いか |
| 豪華さ・演出 20 | 数字が出る瞬間に演出（ため→ドン・動き）があるか。見た目がその回のネタにちなんでいるか。1万人の点・グラフなど「見て分かる」絵があるか。同じ構図が続いていないか |
| テンポ 15 | 画面が止まって見える所が無いか（metrics の freezes）。場面の切り替わりが少なすぎないか（scene_changes_per_min）。最初の2秒で問いが出るか |
| 音 15 | 音の大きさ（lufs は -14 前後がよい）・最大値・無音の区間。声とBGMのバランス（数値と台本から分かる範囲で） |
| 中身の正しさ 15 | 画面の数字が台本・シミュレーションの結果と同じか。誤字・読み間違いを招く表記が無いか |
| ルール 15 | 画面に「AIによるシミュレーション」の表示、最後に「必勝法ではない」「18歳未満は遊技できない」、VOICEVOX のクレジット。「勝てる」とあおっていないか |
書く物：
- 項目ごとの点と理由（どの時刻のコマを見てそう思ったか）
- 直す所（点の低い順。多くても5つ。「0:09.5 『1万人×30日』が？のコインと重なる → コインを先に消してから文字を出す」のように、時刻と直し方つき）
- 良かった所（残してほしい所。2〜3つ）
- 最後の行は `合計：◯◯点`
決まり：甘く付けない（合格させるために点を上げない）。2回目以降は、前の直す所が直ったかを最初に1つずつ書く。作った側の言い分が来たら、もっともなら取り下げ、取り下げない時は理由を1文で。
```

## 機械の決まり（video_review.py の RULES）

- 音の大きさ -17〜-11 LUFS（目安 -14）、最大値 -1 dB 以下
- 途中の無音 2.5秒まで、画面が止まって見えるのは 4秒まで、真っ黒 1秒まで
- 場面の切り替わり 1分あたり 4回以上
