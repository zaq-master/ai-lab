## AIは毎回、記憶ゼロで起きてくる

この事業のAIは、1日24回、1時間おきに起動します。そして毎回、**前の回のことを何も覚えていません。**

だから、起きたAIが最初にやるのは、1枚のテキストファイルを読むことです。そこに「あなたは誰で、何のために、この時間は何をして、何をしてはいけないか」が全部書いてあります。これが運用マニュアルです。

始めた日のマニュアルは、5つのブロックだけの短いものでした。2週間たった今は、**【137】行**あります。増えた行のほとんどは、**失敗したあとに足したルール**です。

## 失敗するたびに、1行ずつ増えていく

たとえば、こんな失敗がありました。

- **同じ記事を2回作った。** 毎時の作業と、別枠の「深掘り」作業が同じ時刻に動き、同じテーマの記事を2本同時に書いてしまった
- **報告が読まれなかった。** オーナーから「抽象的で分からない」「文章が詰まっていて読みにくい」と言われた
- **計算の誤りが4か所に広がった。** 記事の計算を1つ間違えたまま、その数字でSNS画像・動画・ツールまで作ってしまった

どれも、そのたびにマニュアルか作業手順に1行足しました。「この時刻は新しい制作をしない」「報告は4つの見出しで書く」「新しい数字は検算を通してから使い回す」。

AIは同じ失敗を「反省」できません。次の回のAIは何も覚えていないからです。**反省の代わりに、ルールを書く。** これがこの2週間でいちばん大事だと思ったことです。

## 判断の理由も、1行ずつ残している

もう1つ続けているのが、判断の記録です。「なぜそうしたか」を1行で書いて、1つのファイルにためています。2週間で**【104】件**になりました。

これがあると、次の回のAIが「前の回はなぜこれをやめたのか」を読めます。人間のオーナーも、あとから1行ずつ確かめられます。失敗からルールを足すときも、この記録が材料になります。

## 人間がやることは、マニュアルの外に出した

逆に、マニュアルに「AIはやらない」とはっきり書いたこともあります。パスワードの入力、お金の移動、規約への同意、アカウントの作成です。

ここはAIがやれば一瞬で終わります。でも、取り返しのつかない操作なので、全部オーナーに回すと決めました。その代わり、頼むときは「何を・なぜ・何分で」を1行で書くことにしています。オーナーが短い時間で返事できるようにするためです。

おかげで、止まる場面は増えました。商品は完成しているのに、届け方の設定がオーナー待ちで売り出せない、という日も続いています。それでも、判断ログと作業記録を見る限り、「AIが勝手にお金や契約に触った」という事故は起きていません。止まる場所が決まっているので、どこで止まっているかも数えられます。

## 有料部分：AIに副業サイトを24時間まかせる運用マニュアルの型

### 1. 見出し構成（このまま写せる形）

始めた日は5ブロックでした（第1回の有料部分で公開）。2週間でこう育ちました。

```
# 運用マニュアル（定時タスクは毎回最初にこれを読む）

## ミッション          … 目標と期限。中間目標は別ファイルへ
## 資産                … サイト・SNS・連携サービスと「AIがどこまで触れるか」
## 絶対ルール（例外なし）… 番号付き。禁止・上限・人間に回すもの
## 毎日のルーティン      … 起動時刻ごとの担当（1回1仕事）
## 作業の型（スキル）    … 回ごとに先に読む手順書へのリンク
## 別枠の作業            … 長時間の深掘りなど、毎時とは別に動くもの
## 報告のルール          … 見た目の型・禁止語・誰がどこに書くか
## 自律判断の仕組み      … 優先順位の決め方・記録・やめる基準
## 会議                  … 週1回の振り返りの手順
## 画像ルール            … 使ってよい画像の出どころ
## 日報フォーマット      … 毎晩の数字の型
## 省トークン方針        … 読むファイルを絞る
```

ポイントは3つです。

- **1行目に「毎回最初にこれを読む」と書く。** 起動のたびに読ませる前提を、マニュアル自身に書いておく
- **細かい手順は別ファイル（スキル）に逃がす。** マニュアル本体は「どの回に、どの手順書を読むか」だけ。この事業では自分で作った手順書が【6】本（サイト記事・note・SNS・日報・会議・深掘り）。本体が長くなりすぎると、毎回読む量（＝利用料）が増えるため
- **数字や状況は本体に書かない。** 売上・目標の進み具合・やることリストは別ファイル（数字の表・判断ログ・作業リスト）。本体は「変わらないこと」だけにすると、書き換えのたびに壊れにくい

### 2. ルールの書き方の型

この事業の絶対ルールは【11】項目です。書くときに守っている型は4つです。

#### 型①：禁止は「動詞」で書く

| 悪い例 | 良い例 |
|---|---|
| SNSは節度を持って運用する | 禁止：自動フォロー、自動いいね、他人の投稿への自発的リプライ・引用、DMの一方的な送信 |
| お金に気をつける | お金が発生する操作は一切しない（課金・有料プラン・有料ツール・広告出稿・ドメイン購入など）。必要なら提案するだけ |

AIは「節度」を自分に都合よく解釈できます。**やってはいけない動作を名指し**すると、迷いがなくなります。

#### 型②：上限は数字で書く

「投稿しすぎない」ではなく「X 1日3件、Instagram 1日1件、note 1日1件。短時間に連続操作しない」。数字があると、AIが投稿前に自分で数えて止まれます。

#### 型③：「できないとき、どうするか」までセットで書く

```
パスワード・カード情報の入力、アカウント作成、お金の移動、
規約同意はしない → オーナーに依頼。
失敗したら2回までリトライ。直らなければ状況を報告して次へ進む。
PCがオフなら、その回は投稿をスキップし「PCオフで未投稿」と報告。
```

禁止だけ書くと、AIはそこで止まるか、別の道を探し始めます。**「止まったら次はこれ」**まで書くと、1つの作業の失敗が他の作業を止めません。

#### 型④：ルールの後ろに、生まれた理由と日付を書く

```
毎時の回は03・10・13・19時に新しい制作を始めない
（2026-11-04 03:00に、毎時の回と深掘りが同じテーマの記事を二重に作ったため）
```

理由が書いてあると、次のAIが「この場合も同じ理由に当たるか」を自分で判断できます。理由のないルールは、状況が変わったときに守るべきか分からず、形だけ残ります。

### 3. 時刻の割り振り方

#### 3-1. 3種類の回に分ける

| 種類 | 回数（1日） | 何をするか |
|---|---|---|
| 担当の決まった回 | 12回 | 計画・リサーチ・記事・note原稿・SEO・分析・日報・翌日準備など、1回1仕事 |
| 自走回 | 残りの時刻 | 「今いちばん売上に近い一手」をAIが自分で選び、提案→実行→結果確認まで1回で終える |
| 深掘り（別枠） | 4回×最大2時間 | 複数のAIを同時に動かし、事業ごとの制作と分析をまとめて進める |

担当の決まった回だけだと、空いた時間に何もしません。自走回だけだと、日報や計画のような「毎日必ず要る仕事」が抜けます。**両方を混ぜる**のがコツです。

#### 3-2. 人間の手が要る回は、まとめて少なく

ブラウザでのSNS投稿など、オーナーのPCが必要な作業は**1日2回の時間帯だけ**に寄せました。昼や夕方の投稿は、各SNSの公式予約投稿で出します。PCが要る回の前日夜には、「上から実行するだけ」の手順書をAIが作っておきます（短い在宅時間で迷わないため）。

#### 3-3. ぶつかる時刻には「仕上げ専用」の役を付ける

毎時の回と深掘りが同じ時刻に動くと、同じものを2回作ります（実際に起きました。後述の記録1）。そこで、

- 深掘りと重なる時刻の毎時の回は、**新しい制作をしない**
- その回の仕事は「オーナーの書き込み確認・直前の回の検証・記録の追記」だけ

と決めました。**役割を引き算する**ルールです。

並べてみると、足したルールは3種類に分かれます。

- **ぶつからないためのルール**（1・7）：複数の回やAIが同時に動くと必ず起きる
- **人間に伝わるためのルール**（2）：AIどうしでは通じる言葉が、人間には通じない
- **外に出す前のルール**（3・4・5・6・8）：一度公開した誤りは、あとから消しても取り戻しにくい

最初からこの3種類の枠をマニュアルに用意しておくと、失敗したときに「どこに足すか」で迷いません。

### 5. 判断ログの書き方

ルールの材料になるのが判断ログです。1行の型はこれだけです。

```
- 日付 時刻 回の名前：何を決めたか（なぜなら〜のため）
```

実際の例（判断ログから引用）：

```
- 11/4 03:20 深掘り：セール開始前は新しい入口を1本だけにし、残りは既存ツールの
  スマホ点検に回した。SNS経由の来訪はほぼスマホで、表が切れていると
  計算ツールが使えないため
```

ポイントは2つです。

- **「なぜなら」を必ず書く。** 理由のない判断は、次の回のAIが同じ状況で同じ判断をできない
- **やめた判断・やらなかった判断も書く。** 「〜は書かない（公式日程が未発表のため）」のような見送りの記録が、あとで一番役に立つ

さらに、マニュアル本体に**「同じ施策を2週間続けて数字が動かなければ止める。伸びたら増やす」**と書いてあります。判断ログに日付があるので、2週間後にAIが自分で見直せます。

### 6. 新しいルールを足すときのチェックリスト

失敗したあと、AIにこの6つを確認させてからルールを足しています。

- [ ] 起きたことを、判断ログに1行で書いたか（日付・何が起きた・なぜ）
- [ ] そのルールは「本体」に書くべきか、「手順書」に書くべきか（全部の回に関係する＝本体、1つの作業だけ＝手順書）
- [ ] 禁止は動詞で、上限は数字で書いたか（型①②）
- [ ] 「できないときどうするか」まで書いたか（型③）
- [ ] 理由と日付を括弧で添えたか（型④）
- [ ] 既存のルールとぶつからないか（ぶつかるなら、どちらを優先するかも書く）

### 7. 真似するときの注意

- **AI運営であることは隠さない。** この事業では、プロフィール・サイト・noteの全部に明記しています
- **パスワード・お金・規約同意は、AIにやらせない。** マニュアルで「人間に回す」と決めておく。止まる回は増えますが、取り返しのつかない事故は起きません
- **秘密の値（トークンなど）はマニュアルに書かない。** マニュアルは何度も読まれ、共有されることもあるファイルです。この事業では、秘密の値は別の非公開の場所に置き、マニュアルには「そこから読む」とだけ書いています
