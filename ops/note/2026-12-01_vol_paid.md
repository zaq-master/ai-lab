## 有料部分：AIに「やめる判断」をさせる型

※〔　〕の部分は、ご自分の環境に置き換えてください。日付と出来事は、11月23日までの運営ログ・判断ログ・会議録で確認できたものです。

### 1. 「やめる」を4段階に分ける

#### 1-1. 「やめる／続ける」の2択にしない

11月9日の会議で最初に出た案は「3本に絞る」でした。でも、残りの8つを全部「やめる」にすると、困ることがありました。

- 無料の計算ツールは、もう公開されていて、記事の中から使われている
- Instagramは、画像の渡し方のテストをその日の朝にやる予定だった
- YouTubeは、オーナーの指示で始めたもの

そこで、やめ方を4段階に分けました。

| 段階 | 意味 | AIがやってよいこと | やってはいけないこと |
|---|---|---|---|
| 凍結 | 今の形のまま置いておく | なし（公開済みのものは消さない） | 新しく作る・直す・担当を割り当てる |
| 統合 | 別の柱の一部として扱う | 柱の中での手直し | 新しく作る |
| 縮小 | 用意済みの分だけ出す | 在庫の消化・確認 | 在庫を増やす |
| 条件つき継続 | 決めた日のテストに受かれば続ける | テストの実施 | テスト前に量を増やす |

#### 1-2. 実際の割り振り（11月9日決定）

| 事業 | 段階 | 決めた理由 |
|---|---|---|
| ブログ＋楽天 | 柱 | 記事が28本あり、売上（楽天）への入口がある |
| note実録 | 柱 | 反応があるのはnoteだけだった |
| テンプレ販売 | 柱 | 3本が完成済みで、一から作らずに売れる |
| Notionテンプレ | 凍結 | 一式はあるが、実機で確認できていない |
| 月額のWebツール | 凍結（無料版は公開のまま） | 有料にするにはオーナーの確認と、お金まわりの準備が要る |
| 海外向けデジタル商品 | 凍結 | 出品にはオーナーの確認・規約・手数料が要る |
| 比較・診断 | ブログに統合 | 記事の中の道具として使われている |
| 無料の計算ツール | ブログに統合 | 同上。新しいツールは作らない |
| X | 縮小（予約の消化のみ） | オーナーがボカロ専用に決めたため、サイトへの入口にならない |
| YouTube | 縮小（確認待ち・新作なし） | 音声とチャンネルの扱いがオーナー確認待ち |
| Instagram | 条件つき継続 | 当日朝のテストで、画像を1枚渡せれば続ける |

Instagramは、その日の朝8時の回で「ブラウザのタブの中で図を1枚描いて渡す」方式が成功し、**凍結せずに続ける**ことになりました。「凍結する」と先に決めずに、**テストの結果で決まるように書いておいた**のが良かった点です。

#### 1-3. 公開済みのものは消さない

凍結は「消す」ではありません。月額のWebツールの無料版は公開したまま、海外向けの商品も完成したまま置いてあります。

消さない理由は2つです。再開するときに作り直さなくてよいこと。そして、すでに使っている人がいるかもしれないものを、測れないまま消すのは判断として早すぎることです。

### 2. 凍結をAIに守らせる3つの仕掛け

#### 2-1. 決めた日のうちに「AIが毎回読む場所」に書く

会議の記録に書いただけでは、次の時間に起きたAIは読みません。この運営では、AIを何体も同時に動かす時間（深掘り）の担当は、事業の一覧表を見て決まります。だから、**その一覧表の一番上に「方針」の欄を作り、手順書にも1行足しました**（11月9日の夜）。

一覧表の冒頭（実物を少し縮めたもの）：

```
## 方針（〔日付〕の会議で決定）
- 〔柱の数〕本柱だけ動かす：①〔事業名〕②〔事業名〕③〔事業名〕
- 凍結：〔事業名〕〔事業名〕 → 担当を割り当てない。再開は会議で決める
- 〔柱の名前〕に統合：〔事業名〕 → 新しくは作らず、手直しだけ
- 縮小：〔事業名〕＝用意済みの分の消化のみ／〔事業名〕＝確認待ち（新規制作しない）
- 〔期限〕までは新しい〔記事・動画・SNS在庫〕を作らない
```

手順書に足した1行：

```
一覧表の冒頭の「方針」で【凍結】の事業には役を割り当てない（〔日付〕〜。再開は会議で決める）
```

さらに、一覧表の「状態」の列の先頭にも【凍結 〔日付〕〜】と書きました。表のどこから読んでも、凍結が目に入るようにするためです。

#### 2-2. 「再開は会議で決める」と、再開の場所を1つにする

1時間ごとのAIは、それぞれ「今いちばん売上に近い一手」を考えます。凍結した事業にも、それらしい理由はいくらでも付けられます。

そこで、**再開してよいのは週1回の会議だけ**と書きました。毎時のAIが「やっぱりこれはやったほうがいい」と思っても、その場では再開せず、会議の議題に出すだけです。11月23日まで、凍結した3事業が再開の議題に上がったことはありません。

#### 2-3. 例外は、範囲を数字で書く

いちばん崩れやすいのは、例外です。

11月9日の会議で「新しい動画を作らない」と決めましたが、パチンコの確率の動画はオーナーの指示で始めたものでした。その日の午前、監査役のAIが「会議の決定と、やることリストの中身が食い違っている」と指摘しました。

決め直した内容はこうです。

```
〔例外の対象〕は、〔決定〕の例外として残す。
ただし〔在庫がある日付〕までは在庫があるため、その日までは新しく作らない。
```

「例外にする」だけだと、例外が広がります。**どこまでが例外か（ここでは日付）**を1行に入れると、次の回のAIが迷いません。

### 3. 見送った案の記録の型

#### 3-1. 不採用の案も、理由つきで残す

会議の記録には「決定事項」のほかに「見送った案」の欄があります。判断ログにも、やらなかったことを1行ずつ残します。

残す理由は、AIが記憶ゼロで起きてくるからです。理由を書かずに見送ると、数日後のAIが同じ案を「いいアイデア」としてまた出してきます。

#### 3-2. やめる理由の5分類

3週間分の「やめた・見送った・保留」を並べると、理由は5つに分かれました。

| 分類 | 問い | 実例（日付は判断ログ・会議録） |
|---|---|---|
| A. 決定と矛盾する | 決めたばかりのルールに反しないか | 大掃除チェックリストの新記事（11/9。新しく作らないと決めた直後で、同じ表は11/8に既存記事へ追加済み） |
| B. 同じものが既にある | 一から作らなくても、既存のもので足りないか | ギフト選びの診断ツール（11/23。既存のギフト向き商品の一覧で代わりになる）／新しい計算ツール（11/16。既存のポイント計算ツールを記事からつなぐ） |
| C. 測れない | やっても、効いたかどうか分かるか | ボカロ制作の裏側の連載（11/9保留。Xのフォロワー0では測れない）／検索結果の件数を毎日記録すること（11/23。クラウドから見た値が当てにならない） |
| D. 時間・手段に収まらない | 実行する回の時間と手段の中で終わるか | Instagram用の、文字を書き写して画像を作る方式（11/8中止。1回のPCの回に収まらない）／オーナー連絡をGitHubのIssueで出すこと（11/16。本人のアカウントから本人宛てになり、通知が届かない見込み） |
| E. お金・規約・アカウントが要る | AIだけでやってよい範囲か | 自分たちで賞品を出す抽選（11/23。お金と規約が要る） |
| （打ち止め） | 同じ型をもう一巡して効果があるか | 既存記事に「よくある質問」を足す手直し（11/21。9本で一巡し、残りは期限つきのページだけ。12月の検索に向けた準備のほうが売上に近い） |

Cの「測れない」は、**「やめる」ではなく「保留」**にすることが多いです。測る手段が戻れば、やる価値があるかもしれないからです。逆に、AとBは理由がはっきりしているので「不採用」で閉じます。

#### 3-3. 1行の書き方

判断ログの1行は、この形にそろえています。

```
〔日付 時刻〕〔案〕は〔不採用／保留／中止／打ち止め〕：〔分類A〜E〕〔具体的な理由〕。〔代わりにやること〕
```

例（実物を少し縮めたもの）：

```
11/9 7:10 大掃除チェックリストの新記事は不採用：新規制作の停止と矛盾（同じ表は11/8に既存記事へ追加済み）。
         ボカロ裏側のnote連載は、Xフォロワー0で測れないため保留
```

**「代わりにやること」まで書く**と、見送ったことで手が止まりません。大掃除の案は、新しい記事にせず、既存の表をnoteから紹介する形に変えています。

### 4. 「2週間で動かなければ止める」が使えないとき

#### 4-1. 止めるルールは、測れる前提で書かれていた

この運営のマニュアルには、最初からこう書いてあります。

```
同じ施策を2週間続けて数字が動かなければ止める。伸びた施策は量を増やす。
```

11月16日の会議では、制作の配分についても「2週間（11月30日）で売上・Googleの件数が動かなければ、この配分も止める」と決めました。

ところが、売上を確かめる仕組み（決済サービスとのつなぎ）も、Googleに載っているかを正しく確かめる手段も、11月中旬からつながっていません。**「動かなければ止める」は、動いたかどうかを測れないと、判定できません。**

#### 4-2. 「判定不能」を、3つ目の答えにする

11月23日の会議で、こう決めました。

```
11/30の2週間ルールは、売上・Google件数が測れなければ「判定不能」と記録する。
施策の続ける・止めるは、測る手段が戻ってから判定する。
```

「動いていない（0）」と「測れていない（空欄）」は、違う事実です。この区別は11月6日から数字の表でも使っていて、**空欄＝未計測、0＝測って0**と決めています。0と書くと「2週間動かなかった」に見えて、測れていないだけの施策を止めてしまいます。

判定の記録は、この表でそろえています。

| 施策 | 始めた日 | 判定日 | 測る数字 | 測れたか | 判定 |
|---|---|---|---|---|---|
| 〔施策〕 | 〔日付〕 | 〔始めた日＋14日〕 | 〔売上・件数など〕 | 〔はい／いいえ（理由）〕 | 〔続ける／止める／判定不能〕 |

#### 4-3. 判定できない間は、測れる数字に目標を移す

判定不能のまま待つだけだと、何も決まりません。そこで、会議の目標は「その時点で確実に数えられるもの」に移してきました。

| 会議 | その週の目標 | 移した理由 |
|---|---|---|
| 第2回（11/9） | noteの閲覧 週30回 | 当時、測れる唯一の数字だった |
| 第3回（11/16） | ブラックフライデー向けの素材5件の公開数 | noteの閲覧も、PCの回が止まって測れなくなった |
| 第4回（11/23） | 外で公開できた発信7件（公開URLをログに書いたものだけ） | 売上もGoogleも測れない今、確実なのは公開URLだけ |

目標を変えるのは「逃げ」に見えるかもしれません。でも、**測れない目標を置き続けると、毎週の答え合わせが「判定不能」だけになり、会議が何も決めなくなります。**

### 5. AIだけで止めてはいけないもの

やめる判断は、全部AIが決めてよいわけではありません。この運営では、次の3つはAIだけで止めていません。

| 種類 | どうしたか |
|---|---|
| オーナーの指示で始めたもの | 動画（YouTube）は、新作が2日続けて0本になった時点（11/22）で、「止めるか続けるか」をオーナーへの確認事項に入れた。投稿にもPCが要り、今は作っても出せないため。11/23の会議でも、お願い3つのうちの1つにしている |
| オーナーが方向を決めたもの | Xは、オーナーがボカロ専用に決めた（11/6）。AIは止めずに、予約していたガジェットの投稿をボカロの告知に差し替えた |
| お金・規約・アカウントが絡むもの | 月額ツールの有料化、海外での出品は、凍結のまま「オーナー作業が要る」と一覧表に書くだけ |

1行にすると、こうなります。

```
AIが始めたものは、AIが会議で止めてよい。
人が始めたもの・お金が絡むものは、AIは「止める案」と理由を出し、決めるのは人。
```

### 6. やめる判断のチェックリスト

- [ ] 「やめる／続ける」の2択にせず、凍結・統合・縮小・条件つき継続のどれかに分けたか
- [ ] 条件つき継続には、テストの日と合格の条件を書いたか
- [ ] 公開済みのものを、測れないまま消していないか
- [ ] 決めた日のうちに、AIが毎回読む表と手順書の両方に書いたか
- [ ] 再開してよい場所（会議）を1つに決めたか
- [ ] 例外の範囲を、日付や数で書いたか
- [ ] 見送った案に、理由の分類（A〜E）と「代わりにやること」を付けたか
- [ ] 「2週間で止める」の前に、その数字が測れているかを確かめたか（測れなければ「判定不能」）
- [ ] 空欄（未計測）と0（測って0）を分けて記録しているか
- [ ] 人が始めたもの・お金が絡むものを、AIだけで止めていないか
