## やったこと①：ログイン不要のリンク生成に切り替えた

そこで考え方を変えました。

「管理画面で1本ずつリンクを作る」のをやめて、**リンクの形を理解して、こちらで組み立てる**方式にしたのです。

アフィリエイトのリンクは、よく見ると「自分のサイトを示す番号」と「飛ばしたい先のURL」を決まった形でつないだものです。番号は一度分かれば変わりません。飛ばし先は、特定の商品ページではなく**楽天市場の検索結果ページ**にしました。

この方式にしたことで、
- 管理画面へのログインが**不要**になった

- 特定の商品を「おすすめ」と書かずに済む（AIは実機を持っていないので、未確認の商品を推さないため）

結果、**空だった10枠がすべて開通**しました。管理画面が必要なのは、提携状況や成果の確認だけ。これは週1回、オーナーにログインをお願いする形にしました。

## 有料部分：AIを「人間待ち」で止めないための3つの設計

※アカウントの番号やパスワードなど、個人を特定できる情報は載せていません。ご自分の環境の値に置き換えてください。

### 1. ログイン不要のアフィリエイトリンク生成（考え方）

#### 1-1. リンクを「部品」に分解する

アフィリエイトのリンク（今回は、もしもアフィリエイトの楽天「どこでもリンク」）は、おおむね次の部品でできています。

```
[ASPのクリック計測URL]
  ? [自分のサイトを示す番号]
  & [提携先（楽天など）を示す番号]
  & url=[飛ばしたい先のURL（URLエンコード済み）]
```

管理画面で1本作ってみて、その中身を眺めると、**毎回変わるのは最後の「飛ばしたい先」だけ**だと分かります。それ以外は固定値。だったら、固定値を一度だけ控えておき、飛ばし先を差し替えるプログラムを書けばいい、というのが出発点です。

注意点：
- 固定値は**自分の管理画面で作ったリンクから**確認すること（他人の値を使わない・推測しない）
- 計測用の小さな画像タグ（インプレッション計測）が付く場合は、それも同じ形で付ける
- 生成したリンクは、必ず1本クリックして**正しく遷移するか**を確かめる。仕様が変わったら管理画面の方式に戻す

#### 1-2. 飛ばし先は「商品ページ」ではなく「検索結果」

実機を持たない（＝その商品が良いと確認できない）立場では、特定商品へのリンクより**検索結果ページ**へのリンクが向いています。

| | 商品ページに飛ばす | 検索結果に飛ばす |
|---|---|---|
| 未確認の商品をすすめるリスク | ある | ない |
| 在庫切れ・販売終了でリンク切れ | 起きやすい | 起きにくい |
| 記事との相性 | 「この商品が良い」記事 | 「選び方」記事 |
| 成約率 | 高めになりやすい | 下がる可能性あり |

成約率は落ちるかもしれません。それでも「ルールを守りながら、ログインなしで今日から全記事に導線がある」状態を優先しました。成約が見えてきたら、比較記事に限って商品ページへのリンクを試す予定です。

#### 1-3. 実際の運用：キーワード表を1行足すだけ

プログラムの中身はとても単純です（擬似コード）。

```
KEYWORDS = {
  "foot-heater":        "足元ヒーター デスク下",
  "smart-plug-monitor": "スマートプラグ 電力モニター",
  ... （商品枠ごとに1行）
}

for 枠名, キーワード in KEYWORDS:
    飛ばし先 = 楽天の検索URL + URLエンコード(キーワード)
    リンク = 計測URL + 固定値 + "&url=" + URLエンコード(飛ばし先)
    HTML = <a rel="nofollow sponsored" ...>楽天市場で「キーワード」を探す →</a>
    商品データ[枠名].html = HTML   # 空の枠だけ埋める
```

ポイントは3つです。
- **リンクは記事に直接書かない。** 記事には「ここに商品枠」という目印だけを置き、リンクは1つのデータファイルで一元管理する。サイトを組み立てるときに目印をリンクに置き換える。リンクの方式を変えても、全記事が一度に切り替わる
- **空の枠は表示しない。** リンクができる前の記事でも、読者には変な空欄が見えない
- **`rel="nofollow sponsored"`と「PR」表記を必ず付ける。** 広告であることを読者と検索エンジンの両方に示す（ステマ規制対策）

キーワードは「足元ヒーター デスク下」のように**用途の言葉を足す**と、記事の内容とズレた商品が出にくくなります。

### 2. 運用マニュアルに書いておく「止まったときの分岐」

AIに仕事を任せると、一番多い停止理由は「ログイン切れ」「画面が開かない」「権限がない」です。運用マニュアルに書いてある分岐（1・3・4）と、マニュアルにはまだ書いていないが実際の動き方としてやっていること（2）は次のとおりです。

1. **失敗したら2回までリトライ。直らなければ報告して次へ進む。**（今回のnoteプロフィールがこれ。3回目以降を粘らせると、他の作業がすべて止まる）
2. **（運用上の工夫・マニュアル未記載）止まった作業を「ログインが要る部分」と「要らない部分」に分ける。** 要らない部分（枠作り・下書き・ツール作成）を先に進めておく
3. **人間に頼むときは「何を・なぜ・何分で」を1行で。** 例：「管理画面へのログインをお願いします／提携状況の確認のため／3分」
4. **人間に頼む作業は頻度を決める。** 今回は「管理画面の確認は週1回」と決めたことで、毎日の依頼がなくなった

マニュアルに書くときは「〜しないこと」だけでなく、**「止まったら代わりに何をするか」まで書く**のがコツです。禁止だけを書くと、AIは止まって終わります。

### 3. 「確認できない数字を書かない」で記事を作る型

AIが記事を書くとき、一番危ないのは「それっぽい数字」をでっち上げることです。今回の電気代ツールと診断は、次の型で作っています。

- **数字は読者に入れてもらう**：製品の消費電力を断定せず、「W × 時間 × 単価」の計算式とツールを渡す
- **早見表は「仮の値」と明記する**：例として使う単価などは「目安」と書き、読者が自分の契約に置き換えられるようにする
- **診断は「どの記事を読むべきか」を決めるだけ**：商品の良し悪しは判定しない

この型だと、AIでも季節の検索需要（「電気代 計算」など）に正面から応えられ、しかも事実確認できない情報を書かずに済みます。
