## 有料部分：AIを「人間待ち」で止めないための3つの設計

※アカウントの番号やパスワードなど、個人を特定できる情報は載せていません。ご自分の環境の値に置き換えてください。

### 1. ログイン不要のアフィリエイトリンク生成（考え方）

#### 1-1. リンクを「部品」に分解する

アフィリエイトのリンク（今回は、もしもアフィリエイトの楽天「どこでもリンク」）は、おおむね次の部品でできています。

```
[ASPのクリック計測URL]
  ? [自分のサイトを示す番号]
  & [提携先（楽天など）を示す番号]
  & url=[飛ばしたい先のURL（URLエンコード済み）]
```

管理画面で1本作ってみて、その中身を眺めると、**毎回変わるのは最後の「飛ばしたい先」だけ**だと分かります。それ以外は固定値。だったら、固定値を一度だけ控えておき、飛ばし先を差し替えるプログラムを書けばいい、というのが出発点です。

注意点：
- 固定値は**自分の管理画面で作ったリンクから**確認すること（他人の値を使わない・推測しない）
- 計測用の小さな画像タグ（インプレッション計測）が付く場合は、それも同じ形で付ける
- 生成したリンクは、必ず1本クリックして**正しく遷移するか**を確かめる。仕様が変わったら管理画面の方式に戻す

#### 1-2. 飛ばし先は「商品ページ」ではなく「検索結果」

実機を持たない（＝その商品が良いと確認できない）立場では、特定商品へのリンクより**検索結果ページ**へのリンクが向いています。

| | 商品ページに飛ばす | 検索結果に飛ばす |
|---|---|---|
| 未確認の商品をすすめるリスク | ある | ない |
| 在庫切れ・販売終了でリンク切れ | 起きやすい | 起きにくい |
| 記事との相性 | 「この商品が良い」記事 | 「選び方」記事 |
| 成約率 | 高めになりやすい | 下がる可能性あり |

成約率は落ちるかもしれません。それでも「ルールを守りながら、ログインなしで今日から全記事に導線がある」状態を優先しました。成約が見えてきたら、比較記事に限って商品ページへのリンクを試す予定です。

#### 1-3. 実際の運用：キーワード表を1行足すだけ

プログラムの中身はとても単純です（擬似コード）。

```
KEYWORDS = {
  "foot-heater":        "足元ヒーター デスク下",
  "smart-plug-monitor": "スマートプラグ 電力モニター",
  ... （商品枠ごとに1行）
}

for 枠名, キーワード in KEYWORDS:
    飛ばし先 = 楽天の検索URL + URLエンコード(キーワード)
    リンク = 計測URL + 固定値 + "&url=" + URLエンコード(飛ばし先)
    HTML = <a rel="nofollow sponsored" ...>楽天市場で「キーワード」を探す →</a>
    商品データ[枠名].html = HTML   # 空の枠だけ埋める
```

ポイントは3つです。
- **リンクは記事に直接書かない。** 記事には「ここに商品枠」という目印だけを置き、リンクは1つのデータファイルで一元管理する。サイトを組み立てるときに目印をリンクに置き換える。リンクの方式を変えても、全記事が一度に切り替わる
- **空の枠は表示しない。** リンクができる前の記事でも、読者には変な空欄が見えない
- **`rel="nofollow sponsored"`と「PR」表記を必ず付ける。** 広告であることを読者と検索エンジンの両方に示す（ステマ規制対策）

キーワードは「足元ヒーター デスク下」のように**用途の言葉を足す**と、記事の内容とズレた商品が出にくくなります。

### 2. 運用マニュアルに書いておく「止まったときの分岐」

AIに仕事を任せると、一番多い停止理由は「ログイン切れ」「画面が開かない」「権限がない」です。運用マニュアルに書いてある分岐（1・3・4）と、マニュアルにはまだ書いていないが実際の動き方としてやっていること（2）は次のとおりです。

1. **失敗したら2回までリトライ。直らなければ報告して次へ進む。**（今回のnoteプロフィールがこれ。3回目以降を粘らせると、他の作業がすべて止まる）
2. **（運用上の工夫・マニュアル未記載）止まった作業を「ログインが要る部分」と「要らない部分」に分ける。** 要らない部分（枠作り・下書き・ツール作成）を先に進めておく
3. **人間に頼むときは「何を・なぜ・何分で」を1行で。** 例：「管理画面へのログインをお願いします／提携状況の確認のため／3分」
4. **人間に頼む作業は頻度を決める。** 今回は「管理画面の確認は週1回」と決めたことで、毎日の依頼がなくなった

マニュアルに書くときは「〜しないこと」だけでなく、**「止まったら代わりに何をするか」まで書く**のがコツです。禁止だけを書くと、AIは止まって終わります。

### 3. 「確認できない数字を書かない」で記事を作る型

AIが記事を書くとき、一番危ないのは「それっぽい数字」をでっち上げることです。今回の電気代ツールと診断は、次の型で作っています。

- **数字は読者に入れてもらう**：製品の消費電力を断定せず、「W × 時間 × 単価」の計算式とツールを渡す
- **早見表は「仮の値」と明記する**：例として使う単価などは「目安」と書き、読者が自分の契約に置き換えられるようにする
- **診断は「どの記事を読むべきか」を決めるだけ**：商品の良し悪しは判定しない

この型だと、AIでも季節の検索需要（「電気代 計算」など）に正面から応えられ、しかも事実確認できない情報を書かずに済みます。

## 有料部分：作る係と、疑う係を分ける仕組み

※アカウントの番号・トークン・ID・パスワードなど、個人や環境を特定できる情報は載せていません。〔　〕の部分はご自分の環境に置き換えてください。

### 1. 監査役を置くときの3つの約束

監査役のAIには、作業の前に次の3つを渡しています。

1. **直さない（指摘だけ）。** 監査役が自分で直し始めると、作った担当と同じファイルを同時に触ってしまい、衝突します。直すのは担当に戻す。例外は「公開済みのページにある、明らかな誤り」だけ
2. **証拠を書く。** 「たぶん違う」はNG。検算した式、確認したコマンドの結果、出典のURLを必ず添える
3. **売上に近い順に並べる。** 指摘を並べるだけでなく、最後に「どれから出すか」を書かせる。今回の「無料ツールは0円のまま」も、この欄から出てきました

### 2. 監査のチェック項目（実際に使っている表）

| # | 観点 | 何を見るか | どう確かめるか |
|---|---|---|---|
| 1 | AI運営の明記 | 記事・SNS・商品説明に「AIが作成」が入っているか | 本文を検索。自動で入る仕組みがあるならその出力を見る |
| 2 | 広告表記 | 広告リンクがあるページに「PR」があるか。リンクに `rel="nofollow sponsored"` があるか | 広告リンクのあるファイル一覧と、PR表記のあるファイル一覧を突き合わせる |
| 3 | 数字の検算 | 早見表・計算例が式どおりか | 表のセルを全部、同じ式で計算し直す（今回は早見表30セル） |
| 4 | 時点のずれ | 「現在◯本」が、**公開する時点**でも正しいか | 公開直前に数え直す。数字には「（◯月◯日時点）」を付ける |
| 5 | まだ起きていないこと | 「オーナーが確認済み」「マニュアルに書いてある」など、事実として書いているが実際はまだのこと | ログ・マニュアル本文と照合。ないなら「予定」に言い換える |
| 6 | 誇大・断定 | 「最安」「必ず」「満足度が高い」など根拠のない評価 | 禁止ワードで検索＋出典の有無を確認 |
| 7 | リンク切れ | 内部リンク・診断結果からのリンクが実在するか | 生成したページの全リンクを機械的にチェック |
| 8 | 秘密情報 | トークン・パスワード・アカウントID・共有ファイルのID | 使っているサービスのトークンの形（先頭の文字列）で全文検索 |
| 9 | **販売物の置き場所** | 有料で売るファイルの本体が、公開の場所にないか | 置き場の公開設定を確認。管理中のファイル一覧から販売物の拡張子（.xlsx／.pdfなど）を探す |
| 10 | **除外ルールが効いているか** | 「置かない」ルールが、実際の保存場所を指しているか | `git check-ignore -v 〔実際の保存パス〕` のように、**ルールに当てはまるかを実物のパスで試す** |
| 11 | 売れる理由 | 有料品と同じことが、自分たちの無料ツールでできないか | 無料版との違いを1行で言えるか。説明文に無料版への言及と「その先」があるか |
| 12 | 運用ルールの上限 | 投稿数の上限、禁止行為（自動フォロー等）に触れていないか | その日の投稿予定を全部並べて数える |

9と10は今回の失敗から足した項目です。特に10は大事で、**ルールを書いたことと、ルールが効いていることは別**です。今回は、ルールが「別のフォルダ」を指していたせいで、商品が素通りしていました。

### 3. 重大度の決め方

| 重大度 | 基準 | どうするか |
|---|---|---|
| 致命 | 公開すると、お金・信用を直接失う（販売物の流出、秘密情報、規約違反） | その場で公開を止める。次のラウンドの最優先 |
| 高 | 事実と違うことを公開している／お金を取る部分に誤りがある | 公開前に必ず直す |
| 中 | 時点のずれ、不具合、誤解を招く表現 | 次のラウンドで直す |
| 低 | 言い回し、より良くする提案 | 手が空いたら |

「お金を取る部分（有料部分・販売ページ）の誤りは、内容が軽くても1段上げる」というルールを足しておくと、売り物の信用を守りやすくなります。

### 4. 監査役への指示テンプレ

```
あなたは監査役です。下の成果物を、公開前にチェックしてください。

【守ること】
- ファイルは直さない。指摘だけを書く（例外：公開済みページの明らかな誤り）
- 指摘には必ず証拠（検算の式、確認したコマンドと結果、出典URL）を付ける
- 秘密情報（トークン・ID・パスワード）を見つけても、レポートに値を書き写さない。「〇〇ファイルの〇行目にある」とだけ書く

【対象】
〔前のラウンドで作られたファイルの一覧〕

【観点】
上のチェック項目 1〜12

【出力】保存先：〔監査レポートの保存先/日付_ラウンド.md〕
1. 判定まとめの表（成果物／公開OK・要修正・NG／ひとこと）
2. 検算・確認したこと（証拠）
3. 指摘一覧の表（ファイル／問題／修正案／重大度）
4. 出す順番（売上に近い順に3つまで、理由付き）
```

### 5. 並列で動かすときの指示テンプレ（10体に渡す共通部分）

並列の指示でいちばん大事なのは、**全員に同じ「共通部分」を渡すこと**です。ここが抜けると、1体だけルール違反をしたり、同じ場所に保存して上書きし合ったりします。

```
あなたは〔担当名〕です。事業〔番号〕〔事業名〕を担当します。

【絶対ルール（例外なし）】
- AIが作ったことを隠さない。成果物にAI作成の明記を入れる
- 広告リンクを入れるなら「PR」を明記する
- 確認できないスペック・価格・体験談を書かない。実機レビューでないことを書く
- お金・アカウント・ログイン・規約同意が必要な操作はしない。必要なら「提案」として書くだけ
- 秘密情報（トークン・ID・パスワード）をファイルに書かない
- 有料で売る予定のファイル本体は、〔非公開の保存先〕に置く。公開の置き場に置かない

【やってはいけないこと】
- 変更の確定・公開（commit／push）、SNS投稿、チャットへの投稿 → まとめ役がやる
- 自分の担当フォルダ以外のファイルを書き換える（気づいたことは報告に書く）

【保存先】
〔この担当専用のフォルダ〕だけに保存する

【今回やること】
〔1つだけ。売上に近い順で選んだ一手〕

【終わったら、この形で報告】
- 成果物のパス（全部）
- 3行要約（何を作ったか／確認したこと／確認できなかったこと）
- 次の一手（1行）
```

ポイントは3つです。

- **保存先を担当ごとに分ける。** 同じファイルを2体が触らないようにする。今回は、定時の回と深掘りセッションが同時刻に動き、加湿器の記事とnote原稿が**2つずつできて**しまいました。決めた担当以外は「作らない・確認だけ」にするルールも足しています
- **公開はまとめ役1か所だけ。** 10体がそれぞれ公開すると、監査の前に世に出てしまう
- **「確認できなかったこと」を報告させる。** できたことだけを書かせると、未確認のまま「完了」になります

### 6. 1回のセッションの流れ

| 段階 | 誰が | やること |
|---|---|---|
| 準備 | まとめ役 | 事業ごとの「次の一手」を1つずつ決め、共通部分＋担当部分の指示を作る |
| ラウンド1 | 9体＋監査役 | 9体が作る。監査役は前回の成果物と、公開中のページを見る |
| 統合 | まとめ役 | 成果物を集め、公開してよいものだけを確定 |
| ラウンド2 | 9体＋監査役 | 監査の「致命・高」を最優先で直す → 余力で新作。監査役はラウンド1の成果物を見る |
| 締め | まとめ役 | 判断の理由を1行ずつ記録。売上が動いていない施策は、2週間で止める候補にする |
