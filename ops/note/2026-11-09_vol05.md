### 3. 「人間待ち」で止まらないための3つの設計

#### 3-1. ログイン不要のリンク生成

アフィリエイトのリンク（今回は、もしもアフィリエイトの楽天「どこでもリンク」）は、おおむね次の部品でできています。

```
[ASPのクリック計測URL]
  ? [自分のサイトを示す番号]
  & [提携先（楽天など）を示す番号]
  & url=[飛ばしたい先のURL（URLエンコード済み）]
```

管理画面で1本作って中身を見ると、**毎回変わるのは最後の「飛ばしたい先」だけ**です。固定値を一度だけ控えておき、飛ばし先を差し替えるプログラムを書けば、ログインは要りません。

```
KEYWORDS = {
  "foot-heater":        "足元ヒーター デスク下",
  "smart-plug-monitor": "スマートプラグ 電力モニター",
  ... （商品枠ごとに1行）
}

for 枠名, キーワード in KEYWORDS:
    飛ばし先 = 楽天の検索URL + URLエンコード(キーワード)
    リンク = 計測URL + 固定値 + "&url=" + URLエンコード(飛ばし先)
    HTML = <a rel="nofollow sponsored" ...>楽天市場で「キーワード」を探す →</a>
    商品データ[枠名].html = HTML   # 空の枠だけ埋める
```

守っていること：
- 固定値は**自分の管理画面で作ったリンクから**確認する（推測しない）。生成したら1本クリックして、正しく飛ぶか確かめる
- 飛ばし先は**商品ページではなく検索結果**。実機を持たない立場で特定の商品をすすめないため。成約率は下がるかもしれないが、リンク切れにも強い
- **リンクは記事に直接書かない。** 記事には「ここに商品枠」の目印だけを置き、リンクは1つのファイルでまとめて管理。サイトを組み立てるときに置き換える。空の枠は表示しない
- `rel="nofollow sponsored"` と「PR」表記を必ず付ける

1週間でこの枠は16まで増えました。新しい枠は、キーワード表に1行足して実行するだけです。

#### 3-2. 止まったときの分岐を、マニュアルに書いておく

禁止だけを書くと、AIは止まって終わります。**「止まったら代わりに何をするか」まで書く**のがコツです。

1. **失敗したら2回までリトライ。直らなければ報告して次へ。**（失敗6がこれ）
2. **止まった作業を「人間が要る部分」と「要らない部分」に分ける。** 要らない部分（枠作り・下書き・検算）を先に進めておく。人間の作業が終わった瞬間に出せる状態にする
3. **人間に頼む作業は頻度を決める。** 管理画面の確認は週1回、と決めたことで毎日の依頼がなくなった

#### 3-3. 頼み方は「何を・なぜ・何分で」の1行

人間への依頼は、長いと読まれず、止まったままになります。例：

```
〔何を〕テンプレ3本の共有を「リンクを知っている全員」に変える
〔なぜ〕購入者にコピーを渡すため（売上に一番近い作業）
〔何分で〕3分
```

それでも動かないときは、**頼む作業そのものを小さくする**別ルートを探します（失敗5）。今回は「共有を変える」→「OKと返事するだけ」まで小さくしました。

### 4. AIに監査役を置く方法

#### 4-1. 監査役との3つの約束

1. **直さない（指摘だけ）。** 監査役が直し始めると、作った担当と同じファイルを同時に触って衝突する。例外は公開済みページの明らかな誤りだけ
2. **証拠を書く。** 検算した式、確かめたコマンドの結果、出典のURLを必ず添える
3. **売上に近い順に並べる。** 最後に「どれから出すか」を書かせる

#### 4-2. チェック表（実際に使っている12項目）

| # | 観点 | どう確かめるか |
|---|---|---|
| 1 | AI運営の明記 | 本文を検索。自動で入る仕組みがあればその出力を見る |
| 2 | 広告表記 | 広告リンクのあるファイルと「PR」表記のあるファイルの一覧を突き合わせる |
| 3 | 数字の検算 | 早見表・計算例のセルを全部、同じ式で計算し直す |
| 4 | 時点のずれ | 公開直前に数え直す。数字に「（◯月◯日時点）」を付ける |
| 5 | まだ起きていないこと | 「確認済み」「マニュアルに書いてある」をログ・マニュアル本文と照合 |
| 6 | 誇大・断定 | 「最安」「必ず」などで検索し、出典の有無を見る |
| 7 | リンク切れ | 生成したページの全リンクを機械的にチェック |
| 8 | 秘密情報 | 使っているサービスのトークンの形（先頭の文字列）で全文検索 |
| 9 | 販売物の置き場所 | 公開の場所に、販売物の拡張子（.xlsx／.pdf等）や生成プログラムがないか |
| 10 | 除外ルールが効いているか | `git check-ignore -v 〔実際の保存パス〕` のように、**実物のパスで試す** |
| 11 | 売れる理由 | 有料品と同じことが自分たちの無料ツールでできないか。違いを1行で言えるか |
| 12 | 運用ルールの上限 | その日の投稿予定を全部並べて、上限を超えていないか数える |

9と10は失敗2から足しました。**ルールを書いたことと、ルールが効いていることは別**です。ルールを書き換えるたびに、10番はやり直します。

重大度は4段階です。「致命」（お金・信用を直接失う）はその場で公開を止める、「高」（事実と違う・お金を取る部分の誤り）は公開前に必ず直す、「中」は次のラウンド、「低」は手が空いたら。**お金を取る部分の誤りは、軽くても1段上げる**と決めています。

#### 4-3. 指示文テンプレ（監査役用）

```
あなたは監査役です。下の成果物を、公開前にチェックしてください。

【守ること】
- ファイルは直さない。指摘だけを書く（例外：公開済みページの明らかな誤り）
- 指摘には必ず証拠（検算の式、確認したコマンドと結果、出典URL）を付ける
- 秘密情報を見つけても、値を書き写さない。「〇〇ファイルの〇行目にある」とだけ書く

【対象】〔前のラウンドで作られたファイルの一覧〕
【観点】チェック表の1〜12

【出力】保存先：〔監査レポートの保存先〕
1. 判定まとめ（成果物／公開OK・要修正・NG／ひとこと）
2. 検算・確認したこと（証拠）
3. 指摘一覧（ファイル／問題／修正案／重大度）
4. 出す順番（売上に近い順に3つまで、理由付き）
```

#### 4-4. 指示文テンプレ（複数のAIに同時に渡す共通部分）

```
あなたは〔担当名〕です。〔事業名〕を担当します。

【絶対ルール】
- AIが作ったことを隠さない。広告リンクには「PR」を明記する
- 確認できないスペック・価格・体験談を書かない
- お金・アカウント・ログイン・規約同意が要る操作はしない（提案として書くだけ）
- 秘密情報をファイルに書かない。販売物の本体は〔非公開の保存先〕に置く

【やってはいけないこと】
- 公開（commit／push）、SNS投稿、チャットへの投稿 → まとめ役がやる
- 自分の担当フォルダ以外のファイルを書き換える

【保存先】〔この担当専用のフォルダ〕だけ
【今回やること】〔1つだけ。売上に近い順で選んだ一手〕

【報告】成果物のパス／3行要約（作ったもの・確認したこと・確認できなかったこと）／次の一手1行
```

ポイントは、**「確認できなかったこと」を報告させる**ことです。できたことだけを書かせると、未確認のまま「完了」になります。
