## 中
### M1. push のたびに sitemap の全URL（現在19件）を送っている → 公式FAQの「変わったURLだけ」に反し、429の危険あり
- 場所：`.github/workflows/indexnow.yml` 39〜46行（`urls = re.findall(... sitemap.xml ...)` で全件を送信）
- 根拠：IndexNow FAQ に「Submit only when content has changed. Do not resubmit unchanged URLs.」「It is not designed for submitting every URL on your site at once」（全件送信を認めているのは移転やリニューアルのときだけ）とある。429 は「Too Many Requests (potential Spam)」、レート上限は非公開。出典：https://www.indexnow.org/faq ／ https://www.indexnow.org/documentation
- 頻度：docs/ を変えたコミットは 11/02〜11/03 で **27件**（`git log --since=2026-11-02 -- docs`）。毎時の回と深掘りがあるので、1日におよそ20回、変わっていない記事も含めて全URLを送り直すことになる。スパム扱い（429）になると、本当に更新した記事の通知まで通らなくなる
- 自分で書いた ops/seo/indexnow.md の「同じURLを短時間に何度も送らない（変更があったときだけ）」とも食い違っている
- 直し方：
  1. `actions/checkout@v4` に `with: fetch-depth: 0` を付ける
  2. `git diff --name-only ${{ github.event.before }} ${{ github.sha }} -- docs` で変わったファイルを取り、`*.html` を公開URLに変える（`index.html` は末尾スラッシュにし、`docs/sns/`・`docs/og/`・画像は除く）。build.py の `page_url` と同じ規則にする
  3. sitemap の `<loc>` にあるURLだけに絞り、0件なら送らずに終える
  4. 全件送信は `workflow_dispatch` の入力（例：`full: true`）のときだけにする
  5. 補足：`github.event.before` が全部0（新しいブランチ）のときや、取れないときは送信をスキップする

## 軽
### L1. `actions/checkout@v4` がタグ指定でSHAに固定されていない（4行目付近の `uses:`）
- 公式Actionで、権限も read だけなのでリスクは小さい。固定するなら `actions/checkout@<コミットSHA> # v4.x.x` にし、あわせて `with: persist-credentials: false` を付ける（このジョブはpushしないため）

### L2. 「Pages配信を待つ」が今回のデプロイ完了を確かめていない（26〜36行）
- 鍵ファイルは初回から公開済みなので、2回目以降は `sleep 120` の固定待ちと同じになる。Pagesの配信が遅いと、検索エンジンが古いページを取りに行く可能性がある（ただし取りに来るのは後なので、実害は小さい）
- 直し方：鍵ではなく sitemap.xml を取得し、ローカルの `docs/sitemap.xml` と一致するまで待つ

### L3. 送信失敗（429・403等）でワークフローが赤になる（59〜60行 `raise SystemExit`）
- 失敗のたびにGitHubからオーナーに通知メールが届き、手間が増える（「オーナーの関与ほぼゼロ」に反する）
- 直し方：429 は `::warning::` にして exit 0 にする。403/422（設定ミス）だけ失敗にする

### L4. トップの canonical は `/` になったが、内部リンクは `index.html` のまま
- 例：`docs/posts/*.html` のヘッダーにある `href="../index.html"`。docs/index.html には2件ある。正規URLとリンク先が食い違い、弱いながら矛盾したシグナルになる
- 直し方：templates/base.html と build.py のトップへのリンクを `{{prefix}}./`（記事からは `../`）にする

### L5. build.py が毎回 `docs/sns/*.html` を書き換える（noindex の挿入）
- 1回入れば `name="robots"` を見てスキップするので、何度も書き換わることはない。ただ、出力先の手書きファイルをビルドで書き換えるのは分かりにくい
- 直し方（任意）：SNS画像の元HTMLを作るスクリプトの側で `<meta name="robots" content="noindex">` を付ける。robots.txt で `Disallow: /ai-lab/sns/` は効かない（サブパスにあり、robots.txt はドメイン直下にしか置けない）ため、今の meta の方式は正しい
