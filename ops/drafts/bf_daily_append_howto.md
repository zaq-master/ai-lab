# 楽天ブラックフライデー 期間中の更新メモ 追記手順（5分）

対象：content/posts/rakuten-blackfriday-memo.md（公開URL：https://zaq-master.github.io/ai-lab/posts/rakuten-blackfriday-memo.html）
期間：2026-11-19（木）20:00 〜 11-25（水）1:59（楽天公式キャンペーンページで2026-11-16に確認済み）

## だれが・いつ
- 担当：毎日 08:00 の回（ブラウザを使わない回なら、11:00 制作①の回の最初の5分）。1日1回まで
- 追記日：11/20〜11/24（11/19は担当の08:00・11:00がセール開始の20:00より前なので追記しない。初回は11/20）。11/25 以降は追記しない（1:59で終了するため）
- その日すでに追記済みなら（記事内に同じ日付があれば）何もしない

## 何を・どこで確認するか
- 確認先は**楽天の公式ページだけ**：
  - 公式キャンペーンページ https://event.rakuten.co.jp/campaign/point-up/blackfriday/
  - そこからリンクされた楽天公式の企画ページ（event.rakuten.co.jp ／ www.rakuten.co.jp 配下）
- 書いてよいもの：公式ページに書かれている「開催中の企画の名前」「企画の日時・時間帯」「エントリーが必要かどうか」など、ページの文言でそのまま確かめられる事実
- 書かないもの：
  - 価格、割引率、ポイント還元率・倍率、上限額（変わりやすく、誤りが読者の損になるため。推測・計算も禁止）
  - まとめサイト・SNS・ブログ・ショップ個別ページの情報
  - 「お得」「おすすめ」などの評価、体験談
- **確認できなければ、その日は書かない**（「特になし」「準備中」も書かない）。ページが開けない・内容が読み取れない日はスキップしてログに1行残すだけ

## どこに貼るか
記事末尾の `<!-- draft-template ... -->`（公開HTMLには出ない型）のすぐ下。

### 初回（最初の1件）だけ：この塊をまるごと貼る
期限タグ行・見出し・1件目の間に**空行を入れない**（空行があると、11/25以降の自動非表示が効かなくなる）。

```
<!-- blackfriday-2026-11 期間中の更新メモ -->
## 期間中の更新メモ（楽天公式で確認できたことだけ）
- **11/DD（曜）**：
  公式で確認した事実（1行）
  出典：[ページ名](公式ページのURL)（11/DD HH:MM 確認）
```

### 2件目から：最後の行の直後に3行を足す（空行なし）
```
- **11/DD（曜）**：
  公式で確認した事実（1行）
  出典：[ページ名](公式ページのURL)（11/DD HH:MM 確認）
```

- 1件＝「日付／公式で確認した事実（1行）／出典URL」の3行
- 新しい日付を下に足す（古い順）
- 冒頭の【PR】表記はすでにあるので追加不要

## 11/25 以降の自動切替（触らない）
- build.py の `EXPIRE["blackfriday-2026-11"] = "2026-11-25T01:59"` を過ぎると、`<!-- blackfriday-2026-11 ... -->` から始まる塊（空行まで）が自動で消え、「終了しました」の案内（`<!-- ended:blackfriday-2026-11 -->`）が出る
- 更新メモもこの塊に入っているので、期間後は自動で消える。手で消さなくてよい（ただし期限後の最初のbuild＋pushは必要）
- 開催中の表示（`STARTS["blackfriday-2026-11"] = "2026-11-19T20:00"`）：11/19 20:00 以降のbuildで、メモに「開催中です（11/25（水）1:59まで）」、トップの「期間限定」枠に「開催中」の見出しが出る。これも build 時に切り替わるので、**11/19 20:00 以降の最初の回で build→push**（その回の追記と一緒でよい）
- 終了後はメモのタイトル末尾に「（2026年の開催は終了）」が付き、説明文も終了文に変わる（front matter の `ended_title`／`ended_description`）。URLは変わらない

## 11/25 2:00以降の最初の回（必ずやる・5分）
サイトは build した時点の表示のまま公開されるため、**11/25 2:00以降の最初の回**（どの時刻の回でも、最初に気づいた回）で次を行う。
```
git pull --rebase
python3 build.py
grep -c "期間限定" docs/index.html                                   # 0 であること（トップの「期間限定」が消えた）
grep -c "終了しました" docs/posts/rakuten-blackfriday-memo.html       # 1以上であること（「終了しました」が出た）
grep -c "開催中です" docs/posts/rakuten-blackfriday-memo.html         # 0 であること
python3 ops/tests/mobile_check.py
git add -A && git commit -m "HH:MM BF終了の表示切替" && git push
```
- docs/ で上の3つを確認してから push。push後1〜2分で公開ページを開き、同じ表示になっていることを確認してから報告
- ops/log/当日.md に「BF終了の表示切替：build→push、トップの期間限定が消え『終了しました』表示を確認」を1行

## 公開
```
python3 build.py
grep -c "draft-template" docs/posts/rakuten-blackfriday-memo.html   # 0 であること
grep -n "期間中の更新メモ" docs/posts/rakuten-blackfriday-memo.html   # 追記した見出しが出ていること
python3 ops/tests/mobile_check.py
git pull --rebase && git add -A && git commit -m "HH:MM BF更新メモ 11/DD" && git push
```
- push後1〜2分で公開ページを開き、追記が出ていることを確認してから報告（verification-before-completion）
- ops/log/当日.md に「BF更新メモ追記：<事実の要約>（出典URL）」を1行。追記しなかった日は「BF更新メモ：公式で新しい事実を確認できず、追記なし」
