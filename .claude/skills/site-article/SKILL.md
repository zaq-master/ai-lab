# サイト記事の型

## 0. テーマ選び（2分以内）
- ops/ideas.md の未着手から1つ。なければ「具体的な悩み＋条件」の検索語を1つ決める（例：「スマートリモコン 賃貸 エアコン2台」）
- 大手が独占する広い語（「充電器 おすすめ」等）は避ける。content/posts/ に同じテーマがないか ls で確認

## 1. 下調べ（並列）
Agentツールでサブエージェント2体を同時に起動して時間を短縮する：
- A：公式情報・規格・公的データの確認（数値は出典URL付きで返させる）
- B：検索上位記事の見出し構成と、読者の疑問のリスト化（本文のコピーは禁止、構成の把握のみ）
確認できない数値は書かない。価格は書かず「販売ページで確認」とする。

## 2. 本文（2,000〜4,000字）
ファイル：content/posts/<英小文字-ハイフン>.md
```
---
title: 検索語を含む具体的なタイトル｜補足
date: YYYY-MM-DD
description: 120字以内。誰の何の悩みをどう解決するか
category: 既存カテゴリから（デスク環境／充電・電源／スマートホーム／季節家電 など）
---
```
構成：結論を先に1〜2文 → 仕組み／選び方 → 早見表（表は1つ以上）→ 注意点 → まとめ → 関連記事への文中リンク1本以上
- 商品枠：`<!-- products: key1,key2 -->` を早見表の直後に置く。新しい商品カテゴリなら content/products.json に `{"label": "...", "html": ""}` を追加（htmlはPC回で埋める）
- 実機レビューのような体験談は書かない。「〜という声が多い」等の作り話も禁止

## 3. 公開
```
python3 build.py && git add -A && git commit -m "HH:MM 制作：<タイトル>" && git push
```
- 公開前チェック（commitの前、build.py の後）：`python3 ops/tests/mobile_check.py`（スマホ・PC・ダークモードの表示崩れ。終了コード1なら直してから公開）
アイキャッチ・関連記事・sitemapは build.py が自動生成する。push後1〜2分で公開。

## 4. 記録
- ops/ideas.md の該当行に✅
- ops/log/当日.md に1行、Slack報告に記事URLを入れる
