# パチンコ1万人シミュレーション動画の作り方

## いちばん大事な決まり
- **最初に `side/pachi3d/VIDEO_KNOWLEDGE.md`（動画制作の知識ノート、2026-11-25 GitHubの7リポジトリから取り込み）を読む**。演出プラン→「読み」の表→cues表→画面の型→数字の見せ方→花字→アリスの演技→音→点検 の順で守る
- 動きの部品は `side/pachi3d/lib/motion.js`（バネ・揺れ・数字ルーレット・カメラ等）。書き出し後は `bash side/pachi3d/tools/qc.sh <mp4>`、音の合体は `bash side/pachi3d/tools/loudnorm.sh <映像> <wav> <出力>`（−14 LUFS）
- 完成前に、別のサブエージェントに VIDEO_KNOWLEDGE.md §9 の7項目で辛口採点させ、直す点（最低1つは驚きを増やす）を反映してから納品
- **オーナーへの説明・報告はすべて日本語**。専門用語は使わず、使うときは括弧で言い換える（2026-11-18 オーナー指示）
- テストは**10秒**で見せる（トークン節約）。OKのあと本番
- 構成は `side/pachi3d/STRUCTURE.md`（ショート7パート／ロング10パート）、語り方・見た目の決まりは `side/pachi3d/PROMPTS.md`

## 1. ネタを決める
- 「パチンコ好きが『それ実際どうなの？』と思うこと」：作戦の検証（勝ったら帰る、ハマり台を狙う）、スペック比較（継続率×出玉、甘デジ vs ミドル）
- 候補と作ったものは `side/research/sim_channel_notes.md`。参考：確率シミュレーション大学（作戦の検証が伸びる）、だいいち!（「同じ○○ならどっち？」が伸びる）
- 実在機の数字は公開情報で確認し、出典を説明欄に。確認できない数字は使わない

## 2. シミュレーションと台本
- お手本：`side/sim1min/build.py`（縦ショート）、`side/pachi3d/build.py`（横ロング）
- 乱数の種は固定。数字は計算結果から自動で台本に入れる（手書きしない）
- 台本は語りかけ調：「〜ですよね？」「実は〜なんです」「結果は…」。1文1つのこと

## 2.5 シミュレーション条件はリアルに（2026-11-18 オーナー指示。全動画で必須）
- 計算は必ず `side/pachi3d/pachisim.py`（リアルな1日のエンジン）を使う。回転数だけの単純計算で済ませない
- 必ず決めて画面と説明欄に出す条件：**回転率（1000円あたり）・交換率（等価／28玉／30玉など）・打つ時間・財布の上限・持ち玉で遊技・やめる作戦**（`describe()` の文をそのまま使う）
- 標準の条件（特に理由がなければこれ）：1000円17回転（台ごとに±0.8のばらつき）・等価・8時間（10〜18時）・財布5万円まで・持ち玉遊技・閉店まで
- 再現する現実：1時間約240回転の上限、大当たり消化とRUSH中にかかる時間、払い出しの実質出玉（約94%）、電サポ中の玉の目減り、現金は持ち玉が尽きてから
- 実在機のスペックは公開情報で確認して Machine(...) に入れ、出典を sources に。確認できない数字は使わない（架空の台にするなら「架空の1/319ミドル」と明記）
- 比較の回は「片方だけ条件が違う」ようにする（回転率・交換率・時間をそろえる）
- 結果は平均だけでなく「真ん中の人（中央値）」「勝った人の割合」「財布を使い切った人の割合」も見る（平均だけだと現実とずれる）

## 3. 読みの点検（必ず）
- `side/pachi3d/yomi.py` の `to_say` → `check` で**全行のカナを表示し、自分で1行ずつ読む**
- 自動では見つからない誤読がある（例：大きすぎ→タイキスギ、「〜、は」→ハ）。見つけたら TABLE に足すか言い回しを変える
- 小数点は「点」に置き換え済み（テンと読む）

## 4. 声・BGM
- 声：**VOICEVOX 四国めたん**（2026-11-18 オーナー決定「めたんで！」、規約にもオーナーが同意済み）。`side/pachi3d/vv_ja.py` の `tts_script(text, sr_out=48000)`＝問いかけ・！は「あまあま」、ふつうは「ノーマル」、数字の文はゆっくり、？と…のあとに間
- クレジット（説明欄と動画の最後に**必須**）：「VOICEVOX:四国めたん」。書かないと1キャラ40万円の契約が必要になる
- 使ってはいけない使い方（zunko.jp 規約）：公序良俗に反する、政治・宗教、情報商材・仮想通貨の宣伝、わざと誤解を招く内容、風俗営業1〜3号・性風俗、反社。→「勝てる」とあおらない、数字は正直に
- 準備：`vv_ja.py` の先頭に書いた curl 4行（GitHubのAPIは使えないので版を直接指定）。ファイルは ~/vv/ に置き、リポジトリに入れない。読みは `create_audio_query(...).kana` で確認できる
- **小春音アミは使わない**：あみたろの声素材工房の規約で「ギャンブル・薬物・武器の宣伝」「年齢制限のある作品・子どもに見せられない使い方」が禁止（2026-11-18 公式規約で確認）
- 予備の声：Style-Bert-VITS2 JVNV（`sbv2_ja.tts_script(text,"jvnv")`、クレジット「音声：Style-Bert-VITS2 JVNVモデル（JVNVコーパス, CC BY-SA 4.0）」）
- BGM：オーナーが手で落とした OpenTracks の曲（`side/pachi3d/assets/bgm/`、リポジトリに入れない）。無ければ自作の `bgm()`

## 5. 映像
- three.js＋HyperFrames。ショートは縦1080x1920、ロングは横1920x1080
- 見た目は毎回ネタにちなんで変える。実機・メーカー・アニメ・ネットの写真は使わない（許可がない限り）
- アリス：`assets/alice_v2/`（表情12枚）。場面ごとに表情を指定、口パク・まばたき
- 数字が出る瞬間に演出（ため→ドン、キラン音、紙吹雪など）

## 6. 確認と描き出し
- `npx --yes hyperframes@0.9.64 snapshot --at ...` で静止画を見て、文字の重なり・はみ出しを直す
- 10秒テスト：`render --start S --end S+10`。本番：`render -o renders/xxx.mp4`（時間がかかるので run_in_background）
- 完成後、長さ・音量・フレームを確認してからオーナーに送る

## 7. 仕上げ
- サムネ：大きな数字＋驚き顔のアリス＋短い一言（ショートは1080x1920、ロングは1280x720）
- description.txt：タイトル案（【数字】＋問い＋【機種名】＋#shorts）、AI制作の明記、条件、出典、「必勝法ではありません」「18歳未満は遊技できません」、BGM・音声のクレジット
- X告知文を `ops/vocalo/x_queue.md` に追記（3〜5行、数字1つ、ハッシュタグ3つまで、動画URLはアップ後に入れる）
- 曲・音声・声のモデルはコミットしない。完成動画 short.mp4 は投稿の読み込みに使うので media/videos/sim/<フォルダ>/ に置いてコミットする（renders/ のままだと公開URLが404になる）
- オーナーへ日本語で報告（やったこと／分かったこと／次）し、動画とサムネを送る

## やらないこと
- 「勝てる」「必勝」とあおる
- お金が発生する操作（有料プラン・課金）
- 他チャンネルのキャラ・見た目のまね（構成や手法だけ参考にする）
